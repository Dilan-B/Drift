## Read this before you build

**`expo-haptics` is a new native dependency.** An existing dev client will not
have it. `haptics.js` wraps it in an optional `require`, so it degrades to
silent no-ops instead of crashing — sliders simply won't buzz until you
rebuild. Nothing else depends on it.

**Four pre-existing dependency mismatches were left alone** (`expo`,
`react-native-get-random-values`, `react-native-svg`, `react-native-webview`).
They predate this commit; `npx expo install --check` lists them. Deliberately
untouched to keep the diff readable — update them separately if you want.

**Dev-tool buttons are `__DEV__`-gated** (`SHOW_DEV_TOOLS` in
`OnboardingScreen.jsx`). They will not appear in TestFlight. Flip the constant
to `true` if you need them in a preview build, and flip it back before
submitting.

## Test in this order — highest risk first

### 1. First-run onboarding on a real build (highest risk)

App selection is now **required** before onboarding can finish, and is no
longer a Pro feature.

This was a hard deadlock a few minutes before the push and the fix is
unverified. `getBlockedSelectionCount()` fails closed — it returns 0 whenever
the native bridge is unavailable — so combining it with a gate that disables
Done, removes Skip, and swallows swipe-to-dismiss trapped the user in
onboarding forever. The gate now only applies when `isNativeBlockingAvailable()`
is true.

Check:
- Fresh signup on a dev/standalone build: Done stays disabled until you pick
  something in Apple's picker, then enables.
- **Expo Go / a build without FamilyControls: the button must read CONTINUE and
  must let you through.** If it doesn't, onboarding is unescapable — that is a
  ship-blocker, not a polish item.
- Swipe-down on the sheet must not escape the gate on a build that can block.

Relevant: `BlockedAppsModal.jsx`, `blockedApps.js` (`getBlockedSelectionCount`).

### 2. Free-tier blocking actually honours the picked apps

Because free users can now pick apps, `applyBlocking()` changed: the user's
selection wins for everyone, and the old category-blanket is now only the
fallback when nothing is picked. Verify a free account's chosen apps really
get shielded at zero balance, rather than the whole social/entertainment
category.

Relevant: `blockedApps.js` → `applyBlocking`.

### 3. The tour

Two fixes, both timing/measurement dependent, both unverified.

- **Add-task spotlight** previously landed on the "TODAY" kicker. The ref
  resolved to the parent `space-between` row under view flattening; an
  `onLayout={NOOP}` on the wrapper prevents flattening. There is also a guard
  that discards any rect wider than 60% of the screen.
  - If it still lands wrong, check *which* failure you have: a **misplaced
    highlight** means flattening is still happening; **no highlight at all**
    means the 60% guard is rejecting a correct measurement.
- **Scroll position**: Today now scrolls to top before measuring. The measure
  delay was raised 380ms → 560ms because the scroll animates ~300ms and
  measuring mid-scroll misplaces every hole. Replay from The Lab waits a
  further 420ms for the tab slide. **If holes are still off on a slower phone,
  that 560ms is the number to raise.**
- Do not "optimise" the `onLayout` handler into caching the rect. It fires on
  layout, not scroll, so a cached position goes stale the moment the user
  scrolls and silently reintroduces the scroll bug.

Relevant: `Drift.jsx` (tutorial measure effect, `TodayView` add button),
`TutorialOverlay.jsx`.

### 4. Dark mode at near-black

Canvas moved to `#050706`, `ink.void` to true black. `ink.border` and
`ink.hairline` were tuned against a much lighter canvas and **may now be too
faint to see**. Sweep every screen for cards that have lost their edges.

Relevant: `theme.js` → `DARK`.

### 5. The Grove (merged Stats + Friends)

Stats moved into The Grove behind a You/Friends toggle. Both halves stay
mounted behind opacity — SocialScreen holds live challenge state that a
remount would drop and re-fetch. Watch for a SocialScreen modal appearing
while the You half is showing.

### 6. The Lab

Toggles for calendar sync, auto-import and place suggestions now live on the
screen and re-read when the tab becomes visible. Confirm they stay in sync
when changed from the deeper modals.

### 7. Drift In

Session length is unrestricted again (15m–5h). The **payout** is capped at
60 minutes; XP is uncapped. Check a >2h session pays exactly 60m and the earn
preview shows "screen time (max)".

### 8. Verifiability bypass (server-side)

`verify-task` now classifies whether a task can plausibly be photographed and
skips verification when it can't. Try "speak with my teacher" (should bypass,
returns `bypassed: true`) vs "gym workout" (should verify normally).

It **fails open toward normal verification** — a classification error falls
through to the real check rather than auto-accepting. There is deliberately no
client flag; one would let anyone mark their own tasks unverifiable and
auto-pass everything.

### 9. Login level-up

Signing in as an existing user must NOT show the level-up modal. Root cause:
sign-in set `screen="app"` while `totalXp` was still 0, so hydrating real XP
read as a level gain. Cold boot was never affected (it hydrates before the
screen switch).

## Known-unresolved

**Drift In placeholder rendering.** Reported as "letter spacing is huge and
most of the sentence is cut off" on the task input. Not reproduced and not
fixed. The font (`DMSans_500Medium`) loads correctly, the input isn't
width-constrained, and nothing sets letter-spacing — no theory matches the
symptom. Needs a screenshot.

**"Could not connect to AI checker" at a gym.** Narrowed, not solved. Edge
logs showed boot/listening/shutdown with zero errors and workers living
exactly 75.01s — that is Supabase's idle TTL, so nothing timed out. It was an
early rejection through a path that logged nothing. Every rejection now logs a
reason code, so **the next occurrence will name itself in the dashboard.**

Most likely the 429: `MAX_PER_HOUR = 5` in `verify-task`. If the logs confirm
that, it's a product decision about the limit, not a bug. The client no longer
reports a server-answered error as a connection failure.
